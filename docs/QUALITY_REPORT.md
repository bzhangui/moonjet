- KV CAS 冲突、历史、TTL、墓碑、清除、重建、初始化监听/断线重建；Object Store 多分块二进制/中文名称/空对象/元数据/链接、CAS、摘要破坏、预算、取消、消费者清理、垃圾审计与显式静默回收。nats.js 3.4.0、nats.go 1.55.0 实际双向互通消息、KV 和 Object Store。

- npm 锁文件重装、全部开发依赖 audit 均0已知漏洞；Go 模块校验通过。该结果不是漏洞不存在的证明。运行适配不依赖官方参考 SDK，源码、测试与传递依赖许可边界见 NOTICE/COMPATIBILITY。
- 本地源码 ZIP 的85个文件逐条匹配显式白名单，并与工作目录 SHA-256/字节一致；独立解压后重新构建、锁文件安装、从归档源码编译官方 Go 参考夹具，全部95项 Node 回归通过。该操作只打包/验证，没有发布注册表。

复测中实际发现并修正了快照恢复精确序号的 wire 类型、领导者路由拼写、空认证回调、监听取消清理和对象墓碑/链接类型校验。高负载故障重测复现选举期间503、已确认消息仍可能重投：新增只读 waitJetStream，测试用稳定事件ID显式重试，按至少一次语义核查，不靠静默自动重发或屏蔽重投“变绿”。

独立归档回归进一步复现同 messageId 尚在处理的10158，测试明确按同ID有界等待，而非换ID绕过去重。对象元数据缺少分块标识时，读取/回收失败关闭，不将未辨认数据当作可删除垃圾。SDK 门禁最终设为已验证0.10.18，依赖本版严格/精确 JSON 能力，高于赛事0.10.16下限，不声称旧 SDK 兼容。

远端补证：[本轮 CI](https://github.com/bzhangui/moonjet/actions/runs/41013569416) 对应源码提交 `2cff700da5d1b553091333de2eeccb4a3c2c66e2`，Windows、Linux、macOS 的检查/构建/四目标/95项回归/三套演示/覆盖与独立运行包均成功；不是沿用0.2.1记录。随后仅整理 Go 参考夹具为标准 gofmt 格式，重新编译并通过3项官方对照/JWT回归。
